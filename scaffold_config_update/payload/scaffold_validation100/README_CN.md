# 可调数量的 scaffold hopping 实验入口

日常只修改 `scaffold_validation100/config.py`。默认输入是上次成功完成的 100 样本批次使用的 10 个配体，种子仍为 2001–2010；这用于重复原配置，不声称是新输入验证。

## 常用参数

| 参数 | 含义 |
|---|---|
| `INPUTS` | 输入清单：`("cdk2", 5)` 表示 examples/cdk2_ligands.sdf 中编号 5 的配体。编号从 0 开始，使用对应的 cdk2_protein.pdb。增删条目改变输入数量。 |
| `SAMPLES_PER_INPUT` | 每个配体生成多少个分子。 |
| `SEED_START` | 每个输入使用从这里开始的连续种子。例如 3001、3002……。 |
| `INPUTS_PER_GROUP` | 一组包含几个输入。同一输入的全部种子保留在同组，以维持相同输入的成功/失败对照范围。 |
| `OUTPUT_PREFIX` | 新输出目录的前缀。每次自动加上时间，不覆盖旧结果。 |

总数 = 输入清单长度 × 每个输入的生成数量。例如：

- 3 个输入，每个 7 次：共 21 次；每组 2 个输入时，分为 14 + 7。
- 10 个输入，每个 25 次：共 250 次；每组 2 个输入时，分为 5 组，每组 50。
- 1 个输入，每个 100 次：共 100 次，保持在同一组。

组数和组内样本上限都由配置推导。最后一组可以不足整组。数量调整会增加实际计算时间和轨迹存储需求，不保证指定次数产生同样多的有效或唯一分子。

输入继续使用原 recorder 支持的 cdk2、tyk2、ptp1b、bace 示例。此次未扩展任意 PDB/SDF 路径或其他模型，未改变原输入合法性检查。显式输入不合格时会报出具体编号；不会偷偷换一个输入凑数。同一配体不要在清单中重复填写，增加 SAMPLES_PER_INPUT 即可；不同输入条件下相同分子图允许存在。

## 运行

在 WSL 终端进入现有项目并激活现有环境：

```bash
cd /home/ljl/projects/flowr_root
source .venv/bin/activate
python scaffold_validation100/run.py --repo .
```

这一条命令完成：准备本次计划 → 生成 → 判别 → 定位 → 候选整理 → 干预与对照 → 汇总。

也可只准备，不开始生成：

```bash
python scaffold_validation100/run.py --prepare --repo .
```

终端会打印 `NEXT:`，照着它运行即可。恢复已准备好的实验必须明确指定目录：

```bash
python scaffold_validation100/run.py --run --repo . --output outputs/你的本次目录
```

`--run` 使用该目录保存的计划，不重新读取 config.py。已经完成的步骤校验通过后会复用；已经失败或中断的步骤不会自动重复尝试，以免改变预定生成数量。修改 config.py 后不带 --run 执行，会开始新的独立实验。

完成后发回终端 `SEND THIS FILE:` 指向的 `validation100_review.zip`。文件名为兼容旧工作流保留，不代表这一批一定是 100 个。总体计划数、实际数量和组数以 summary.json 为准。

## 哪些规则取消、哪些保留

- 不扫描旧 outputs，不强制使用从未出现过的输入，不读取旧 manifest/summary 来估算空间。
- 每次使用明确输入；重复输入和种子表示复现配置，换种子表示再次采样。不同种子不保证输出结构互不重复。
- 不自动判断新颖性。要做未见输入实验，必须事先明确输入清单与对照/排除清单，不能把重复输入实验称作泛化验证。
- 每次保存实际配置、输入哈希、种子、模型/权重/代码版本、本次轨迹、评价、干预和对照结果。
- 本次参数在准备后固定；旧实验记录不完整不会阻塞，但本次输入或证据不完整仍应停止。

## 方法文件

- `config.py`：日常调参页面。
- `settings.py`：检查参数格式，只接受常量，不执行配置里的任意代码。
- `input_selection.py`：保留原输入合法性检查，不包含历史扫描。
- `method_reference.json`：原来已经验证的方法、权重和环境版本；不包含样本数、种子和历史目录。不是日常调参文件，不要修改它来绕过版本核对。
- `run.py`：按配置调度并检查每组/总数、身份和完整性。

旧 `existing_input_selection.py` 和 `frozen_method.json` 随安装备份。前者的历史扫描已移除，后者有价值的方法版本信息保留在 method_reference.json 中。

## 实验方法保持什么一致

生成器、权重、单次生成参数、输入合法性函数、原始/解码判别、定位和 A/B/AB/C 干预及 15 个对照分支保持原方法。record_scaffold_run.py 仍每次生成一个，重复次数由调度器控制；integration_steps=100 仍是生成步数，不是本批数量。

terminal_control.py 只增加 `--max-runs` 参数和相应数量检查、记录；批量入口自动传入实际组大小。直接运行它时仍默认 20，避免旧命令悄悄扩大计算范围。干预优化迭代数、目标函数次数、阈值、修复成功标准未改。

固定片段可移动的 C 分支仍单独统计；未支持的化学/连通性错误不伪装成已修复。仍属于原模型上的结构/几何诊断与末端修复，不能据此声称已经验证跨模型能力或神经根因。

因为改造的是调度与数量管理，源码哈希会更新；旧结果保持原样，不能用新版入口直接续跑旧版计划。可使用更新包中的恢复命令回到旧入口。

本包的软件验证不等于 GPU 实验验证。第一次建议用默认 10×10 和原种子做可比复跑，再按研究需要改数量或种子。实际生物/化学结果以本地执行报告为准。
