# 这次直接运行什么

这是一个可运行的、固定为 50 条续跑的反馈路径实验。只有一个入口：`run_feedback_path.py`。
复用了你已经运行过的原生回放、原子映射、ROOT/RDKit/PoseBusters 评价逻辑。无需重新训练、安装新环境或删除旧输出。

## 1. 放置文件

把 `scaffold_feedback_v1.zip` 上传到 GPU 服务器的项目目录：

`/home/ljl/projects/flowr_root/`

在 VS Code 里打开这个项目，使用之前成功运行 FLOWR.ROOT 的终端。

## 2. 执行完整命令

```bash
cd /home/ljl/projects/flowr_root
source .venv/bin/activate
python -m zipfile -e scaffold_feedback_v1.zip .
python scaffold_feedback_v1/run_feedback_path.py
```

如果你已经在原来成功的环境里，不需要切换环境。脚本会检查 Torch/RDKit 是否与记录一致。

程序默认读取你已经产生的两个目录：

```text
outputs/sh_boundary_screen_v1/bace_lig16
outputs/sh_head_bace_lig16_v3
```

第一个是原始完整生成轨迹，第二个是已通过回放核对的参考记录。这次不重新运行内部观察脚本。
`early_observation_review.zip` 是上一步的精简审阅包；本次实际续跑使用服务器上原来的完整记录。

如果服务器上的目录不同，可以明确指定原目录，不要复制一个名字相近但内容不同的目录：

```bash
python scaffold_feedback_v1/run_feedback_path.py \
  --record-root 原始完整轨迹目录 \
  --head-dir 已核对的参考记录目录 \
  --output-dir outputs/sh_feedback_bace_lig16_v1
```

## 3. 程序会自动完成什么

先验证原始输入、权重、源码、固定原子映射和真实反馈关系。再按以下固定顺序执行：

1. 10 个种子的原样回放。每一步网络输出、随机流以及最终结果必须与原记录一致；未通过就停止。
2. 10 条定向修改：仅在 call 1 修改反馈里的固定 C–N 相对位置，恢复为该次真实固定输入的相对位置；保持反馈中这两个原子的中心不变。
3. 30 条等幅随机方向修改：每个种子 3 条，固定随机种子，方向与定向改变量正交。

具体执行顺序是先全部 10 条原样回放，再按种子执行“1 条定向 + 3 条随机”。合计 50 条。

call 从 0 开始，所以 call 1 是第二次网络调用。本计划要求原记录每步只有一次网络前向，避免把循环细化调用误当成采样步。

修改只发生一次。主生成状态、其它反馈坐标、原子类别、键概率、模型权重和后续生成规则不变。之后由模型自行运行到终点，绝不会把后面的原始轨迹重新喂回。
干预操作使用独立随机数生成器，每条修改与自己的原样回放逐次核对模型随机流。

配置中的原子编号来自预处理后的参考分子：22、23。程序通过已核对映射找到生成器中的固定原子；循环代码没有写死 sampler 原子 2、3 或 seed 50。

## 4. 看什么输出

终端先显示：

```text
[1/50] sham_s42
...
[10/50] sham_s51
[11/50] targeted_s42
...
Completed: True; 50/50
```

`Completed: True` 表示执行完整，不表示修复成功或已经找到根因。
`chemical endpoint: False` 可能是有效的实验结果，不等于程序出错。真正中止会显示 `STOP:` 和具体原因。

输出都在新的目录：

`outputs/sh_feedback_bace_lig16_v1/`

| 文件 | 用途 |
|---|---|
| `feedback_review.zip` | 运行后上传这个文件即可；包含汇总、完整轻量时间序列、修改记录和程序副本 |
| `REPORT.html` | 浏览结果表和各个种子的轨迹图；与 PNG 放在同一目录打开 |
| `feedback_results.csv` | 50 条续跑的早期变化、终态评价、对照和实际修改幅度 |
| `paired_effects.json` | 每个种子的定向效果与三个随机效果并列 |
| `feedback_summary.json` | 执行是否完整、错误、评价是否缺失 |
| `trials/*/feedback_timeline.json` | 每次调用的真实输入、修改前/后的反馈、网络预测以及键概率 |
| `trials/*/replay_checks.json` | 原样复现、随机流匹配和修改范围的检查结果 |

较大的终态张量和出错时的张量诊断留在服务器目录里，不放进精简 ZIP。

## 5. 怎么解释本轮

本轮预先指定的主要观察量是：calls 1–4 中，预测的固定原子对相对位置与真实固定输入相比的平均误差（Å）。同时记录预期键概率。都与同种子的原样回放比较，不用这几个早期量直接给终态分子贴失败标签。

最终分别检查：

- 原始解码是否化学有效、连通、通过 ROOT 固定片段匹配；
- 原槽位固定化学身份是否保持，避免匹配到别处却被误当成指定片段恢复；
- PoseBusters 三维质量；
- 新骨架是否变化；严格外接键模式仅作额外诊断。

没有要求新骨架恢复参考分子，也没有强行把输出键改回三键。主报告以未经修复的原始解码为准，默认重建/修复结果另列。

| 观察到什么 | 可以说什么 |
|---|---|
| 仅早期改善，终态仍失败 | 该反馈修改影响了过程，但不足以修复最终失败 |
| 定向修改改善早期和终态，而且优于等幅随机对照 | 支持这条反馈路径对这个案例的失败有因果作用；仍不证明唯一根因 |
| 定向修改没有优势 | 本次干预未提供支持；不能据此排除全部自条件路径的作用 |

如果改变量接近数值舍入尺度，`informative_magnitude=False`，该条不能用于宣称定向效果优于等幅对照。

完成后停止围绕 seed 50 调时刻、换位置、增幅度。本轮不自动追加任何实验。下一阶段需要冻结方案，在未参与当前选方案的复合物上检验。

## 中断或报错

普通中断后，用同一命令加 `--resume`，已完成且文件校验一致的条目会复用：

```bash
python scaffold_feedback_v1/run_feedback_path.py --resume
```

若出现 `STOP:`，保留目录并上传 `feedback_review.zip`。不要为了继续运行而放宽比较阈值、改 SOURCE_HASHES 或关闭检查。
如果预检查阶段还未形成运行身份文件，脚本会拒绝断点续跑；修正路径/环境后使用新的 `--output-dir`，保留原出错记录。

## 可复用范围和已做的检查

更换同版本 FLOWR.ROOT 的输入时，使用新的配置，提供同格式、已核对的完整轨迹和参考记录。无需为新种子复制一个脚本。它支持固定连接原子及固定片段内相邻原子的反馈路径检验；更换模型架构需要适配器。
这不是能自动识别所有分子错误的诊断器。当前 10 个种子来自同一个复合物，不能凭这 50 次续跑证明跨分子泛化。

已做：150 组不同尺度和精度的修改构造检查；随机数隔离；映射变化；使用真实 ROOT 采样器函数体和合成张量检查原样回放、单次干预、后续自由续跑、错误参考拒绝和异常清理；NumPy JSON 序列化检查。

本打包环境没有你的预训练 GPU 模型，**尚未在这里执行这 50 条真实模型续跑**。`VALIDATION.json` 是软件检查结果，不能替代你运行时的原样回放检查，也不是科学实验结果。

研究设计参考 Meltdown 的受控干预和匹配幅度对照逻辑：<https://arxiv.org/html/2602.11130v2>。本包检验的是分子生成中的预测反馈路径，不宣称复制其点云结论。
