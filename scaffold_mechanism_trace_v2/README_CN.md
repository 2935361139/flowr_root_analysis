## 一次做什么

研究对象仍然是冻结 FLOWR.ROOT 在 scaffold hopping 中的固定片段—新骨架连接。当前集中研究“固定连接位点超价”这一类已观察现象；既有化学有效性、连通性、固定条件保持、三维质量及骨架变化评价不作改写。

1. 核验模型、源码、轨迹、原子映射和既有评价身份。
2. 复现原始完整单次前向；确认只读 hook 不改变结果。
3. 对真实 BondRefine 输入和原生成键输出做逐阶段一致性校验。
4. 在每个窗口内比较以下四组信息的全部 16 种前后状态组合。
5. 分解当步成键分数变化，并对每种组合构建当步原始分子，检查位点超价、全图化学有效性和连通性。

| 四组信息 | 含义 |
| --- | --- |
| fixed_node | 固定原子在成键头入口处的内部节点表征 |
| generated_node | 生成原子在成键头入口处的内部节点表征 |
| geometry | 模型实际使用的距离平方与坐标点积特征 |
| edge_context | 进入成键头的边表征 |

四组是本次比较的内部信息来源，不是四种错误类别，也不覆盖模型所有上游计算。`geometry` 替换的是读出特征，不会把分子坐标直接移回上一时刻。

计划由已有结果自动生成，不在分析代码中指定某个分子、种子、原子或错误时刻。当前数据对应 30 条轨迹、114 个回放状态、55 个窗口（14 次出现、14 次恢复、27 个同输入且该位点无此事件的对照）。若所有窗口均可评估，会有 880 行局部组合比较。无事件的输入仍保留终态读出检查，不能宣称它们都提供了事件对比。因缺少共同有效原子而跳过的窗口会另行记录。

对照来自同一输入的其他种子，仅比较各自的轨迹；不把不同种子的生成原子按编号互相移植。调用编号从 0 开始；一次网络调用不自动等于一次积分更新。早期中间预测超价也不自动意味着最终失败。

## 看哪些文件

| 文件 | 回答什么 |
| --- | --- |
| `status.json` | 是否真正完成、接受多少状态、停在哪个阶段 |
| `capture_checks.jsonl` | 原始回放、只读观察及各成键子阶段是否一致 |
| `path_comparison.csv` | 每个窗口全部16组合是否改变位点超价、其他化学问题或连通性 |
| `contrast_summary.csv` | 每个位点、时刻的四组分数贡献 |
| `pair_scores.csv` | 哪条固定—生成边的判定和分数发生变化 |
| `contrasts/*_checks.json` | 上一状态的选中边及当前状态全图输出能否重现 |
| `report.html` | 便于阅读的汇总与结论边界 |
| `debug/`、`error.txt` | 出错时保留的张量、阶段及错误；不会直接当作零贡献 |

`coalition=15` 是四组全部来自当前状态，必须复现原始输出；`coalition=0` 是所选边的四组全部取自上一状态。`groups_from_previous` 写明替换了哪几组。分数贡献为有正负号的精确四组 Shapley 分解，四项之和必须等于实际分数变化；它不是“根因概率”。连续的预期键级总和只是读出观察量，不替代原生化学判别。

## 修正与验证边界

- 实验读出使用当前模型的原生 PyTorch 模块、原设备、原精度和完整张量形状。NumPy 重算只留下差异诊断，不再决定归因数值。
- 原始回放和原生读出仍需通过严格数值及离散判定校验，没有靠调大容差接受结果。
- 保存 Linear、SiLU、对称化、输出投影和掩码阶段检查。首条失败也保存可检查的张量及错误；部分成功结果会保留。
- 在 Torch 2.11.0 CPU / RDKit 2026.03.6 上，19项软件检查通过。6项原生读出检查使用上传的真实成键头权重配合构造的激活；4项衔接检查使用实际原生构建/化学源码函数和构造分子。详见 `VALIDATION.json`。这些构造数据只验证软件，不是研究发现。
- 本地没有完整冻结权重、原始 `.pt` 轨迹或 CUDA，因此没有声称已经替你跑通完整 GPU 实验。

## 结果能说明什么，下一步怎样决定

本次回答“当步成键头中，哪些信息变化推动了哪些边的分数及局部化学判定变化”。这种局部替换可能产生非自然表征，不能单凭贡献大小或消除当步超价，就认定最终失败的根因。

完成后统一对比：持续失败窗口、自行恢复窗口、无该事件对照。然后固定候选路径与时机，在同一份续跑程序中加入原样回放、针对性干预、幅度匹配的非定向干预等对照，观察最终连接和其他质量指标，再在未用于选择机制的样本上验证。不要对每个样本另写一套解释，也不要反复挑结果直到出现“成功”。

如果当步超价消失却产生断连，只记为局部判定改变；如果所有路径均未表现出特异作用，就不把它们称为根因，应依据保留的证据界定尚未覆盖的上游问题。当前代码只支持已核验的 ROOT 源码和记录格式；换模型需适配内部读出接口。统一代码可复用，不等于已经证明机制跨输入、跨模型泛化。

本次尚不提供原始输入片段原子的归因。内部固定节点表征的分数贡献不能冒充 DiffSHAPer 式输入原子贡献。

参考 Meltdown 的部分是系统比较计算位置、时刻以及受控干预的研究流程。本次四组读出分解是面向 ROOT 的具体设计，不是对 Meltdown 算法的完整复现，也不要求新骨架恢复成唯一参考结构。
