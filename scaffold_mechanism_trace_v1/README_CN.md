# 固定片段—新骨架：成键计算来源追踪

本程序推进 proposal 中的“内部计算来源分析”。它加载原来的冻结 FLOWR.ROOT，回放已保存的真实前向计算，追踪**固定片段连接处的成键分数为什么发生变化**。

分析对象限定为已由原审计确认的固定位点价态异常。其他失败仍由既有评价报告保留；本程序不是任意失败的通用根因识别器。

## 本次复核后的结论

1. **已经找到一条重建环节的明确原因。** PTP1B ligand 1、seed 42：原始固定氧（槽位 3）连接三个单键而超价；本次启用的价态修复随后把它改为碳。实际源码中，`MolBuilder._repair_valence_decode` 向修复函数传入模型概率和搜索限制，没有传入固定原子/固定内部键掩码。当前运行又禁止删除键；对三个单键不能继续降低为更低的非零键级，所以搜索会考虑改元素或电荷，或修复失败。这解释了“修复为什么破坏固定片段”，并没有解释网络为什么先预测出冲突连接。
2. **此前不是所有干预都失败。** BACE ligand 16、seed 50 的固定原子对反馈修正曾恢复化学/片段指标，但三个随机方向对照中也有一个恢复。因此它提供局部因果影响的证据，尚不能证明特定方向优势、唯一上游原因或跨复合物泛化。
3. **两种失败不能直接合并解释。** BACE 的固定内部键/反馈异常，与当前 PTP1B 的固定氧边界超价不是同一表型。本次 PTP1B 在持续异常开始时，所测固定内部原子对的几何误差并不大于多数通过化学/片段检查的同输入轨迹。不能继续默认“误差越大就越容易失败”。
4. **大量重复干预不等于很多独立失败样本。** 当前新批次有 30 条轨迹，但同类终态固定位点价态失败只有一条。14 个异常起始窗口和 14 个恢复窗口是过程观察，不是 28 个独立复合物。

`source_audit.json` 保存源码核对结果。原生成计划中记录的 13 个源文件哈希与上传源码全部一致；另外两个修复辅助文件的哈希来自上传源码，原计划未记录它们，不能把它们写成已验证的历史哈希。以上修复结论描述当前实验代码及记录，不代表已经核实的 FLOWR.ROOT 官方默认行为。

## 本次具体做什么

源码的真实成键路径为：

`ligand_dec.layers → final_bond_norm / final_inv_norm / 坐标读出 → BondRefine → bond_proj → 成键分数`

`BondRefine.message_mlp` 接收四组信息：

| 组别 | 在本程序中的确切含义 |
| --- | --- |
| fixed_node | 固定原子的内部节点表征，已经包含上下文；不是原始固定片段输入本身 |
| generated_node | 待生成原子的内部节点表征 |
| geometry | 该读出实际使用的距离平方与坐标点积两项特征 |
| edge_context | 前面的网络计算积累、归一化后的边表征 |

程序比较同一轨迹相邻两次调用的真实读出输入，将四组信息的前后状态组合成全部 16 种情况，用原来的 MLP 和线性成键头计算分数，使用精确的四组 Shapley 分摊交互作用。**四组贡献之和必须等于实际读出分数变化。** 不训练探针，不从参考分子指定生成原子的正确连接。

这是针对 ROOT 结构设计的局部读出归因，不是声称 Meltdown 原文采用了这套四组 Shapley 方法。借鉴的是其“固定失败现象、沿实际计算定位、受控干预检验、独立样本检验”的研究逻辑。

程序同时执行以下约束：

- 使用原有审计规则自动选择全部异常起始和自行恢复窗口；为每个窗口选择同一输入、同一固定参考原子上无该异常的最小种子作为观察对照。
- 所有轨迹都检查最后一次调用；不同种子的生成原子不假定一一对应，不相互移植特征。
- 每个保存状态先原样回放，再带只读观察钩子回放；两次都必须复现原始各输出张量及离散类别。
- 再用捕获的实际特征和原权重重建成键头，检查分数误差与逐边类别一致，才接受贡献分解。
- 未评估状态为未知，不能用作正常对照；首次瞬时超价、最后连续异常区间与最终失败分开。
- 固定元素/电荷或固定内部键也变化时，会单独标记；不能只凭边界读出解释全部异常。

先查看 `ptp1b_lig1_seed42`、`before=51`、`after=52`、`fixed_slot=3` 对应行。该位置先前已确认由两个单键变为三个单键；这次检查是哪组内部信息推动了成键分数变化。调用号从 0 开始，52 对应第 53 次网络调用。

再比较同一轨迹早期异常/恢复、其他轨迹的恢复窗口和观察对照，避免把正常的逐步成键变化误称为失败机制。

`expected_boundary_order_*` 是生成边的概率加权键级总和，仅作连续观察量，**不是有效性阈值**。正贡献推动分数上升，负贡献抵消。成键类别变化和具体成键分数见逐边表。新骨架允许多样化；绝不要求恢复参考新骨架。

## 这一步做到哪里，下一步往哪里

完成这一步，可以回答：**“在特定调用窗口，实际成键子模块的哪些输入信息推动了分数变化？”**

仍不能直接回答：**“哪一个上游神经计算是最终失败的唯一根因？”** 还没有让修改后的轨迹自由运行至终态。四组最大贡献不是根因概率；固定节点表征的贡献也不是某个原始输入原子的贡献度。混合内部表征可能偏离自然分布，贡献分解依赖所选基线和分组。

之后应依据结果冻结候选通路，再做同条件的局部修改、匹配幅度随机对照和完整原生续跑。例如，若一致证据指向 edge_context，进一步检查写入该边表征的层；若指向 geometry，追踪坐标读出到成键头的路径。解释必须预测连续分数如何变化，以及最终哪种失败指标应改善，不能只凭“修好了一个”宣布根因。

这次计划执行完就停止自动扩展。没有稳定差异也是结果，不自动换种子、时刻、供体或幅度。当前数据已用于机制探索，最终泛化检验应使用未参与选择机制的新输入。可复用代码与已证明机制泛化是两件事。

## 已完成的代码验证

已通过语法检查、9 项离线数值/选择逻辑测试，并用真实审计文件复核了 30 条轨迹、55 个对比和 114 个回放状态的计划。测试包括已知贡献、非线性交互分摊、零变化、方向对称、原子槽位变化、对照映射、未知状态处理。

编写环境没有本地 GPU 模型权重及完整 `.pt` 轨迹，因此**尚未在这里执行该程序的真实 GPU 回放**。程序会在你原来的环境中强制检查数值一致性；不通过就不输出已接受的内部归因。请使用原来 Torch 2.11.0+cu130 / RDKit 2026.03.6 环境，不额外升级依赖。

程序与这版 ROOT 源码及记录格式绑定；同版本下更换输入、种子、元素和固定原子编号由映射自动处理。更换网络结构需要修改适配器，不能保证无需改代码迁移。
