# 本次结论和下一步

**这次不是零收获。** 已核对的 `feedback_review.zip` 中，seed 50 的定向干预恢复了固定片段化学结构。但这不是“唯一根因已经证明”，也不是“完整三维质量全部合格”。

## 1. 实际结果

50/50 条续跑完成，评价无报错。它们来自同一个 BACE 配体输入、10 个种子；原样回放只有 seed 50 不通过化学/片段终态指标。

| seed 50 条件 | 化学有效、连通且通过 ROOT 固定片段匹配 | 固定槽位化学身份 | PoseBusters 全部检查 |
| --- | --- | --- | --- |
| 原样回放 | 不通过 | 不通过 | 不通过 |
| 定向反馈修改一次 | 通过 | 通过 | 不通过 |
| 等幅随机方向 0 | 不通过 | 不通过 | 不通过 |
| 等幅随机方向 1 | 不通过 | 不通过 | 不通过 |
| 等幅随机方向 2 | 通过 | 通过 | 不通过 |

在第 2 次网络调用前，即从 0 开始编号的 call=1，修改上一轮预测传入下一轮的 self-conditioning 坐标。位置是固定连接碳及其固定氮邻居：当前记录的采样槽位 2、3，对应预处理参考原子 22、23。只恢复这对原子的相对位置，保留中心位置；不修改主生成状态、模型权重或键，不覆盖后续状态。

定向修改后，后续第 1–4 号调用的平均相对位置误差从 1.181 Å 降到 0.077 Å，预期三键的平均预测概率从 44.8% 升到 98.4%。最终应保留的固定 C≡N 恢复。另 9 条本来通过化学/片段指标的轨迹仍通过。

支持的结论：**这个早期反馈位置能因果地影响该轨迹的后续预测及固定片段保持。** 本例具体研究的是“连接位点附近固定片段被改写”，不能偷换成所有 scaffold hopping 失败的统一根因。

尚未证明：最上游触发原因、唯一根因、特定修正方向普遍优于随机扰动、跨配体泛化。随机对照的修复必须保留报告。定向修复样本仍未通过 `minimum_distance_to_waters`；固定原子也没有完全恢复原绝对坐标。不要据此宣称完整三维生成成功。

50 条续跑不是 50 个独立失败样本。定向组 10/10 通过，也不是修复了 10 个失败样本：其中 9 个本来就通过。

## 2. 在 VS Code 终端运行

把 `scaffold_validation_batch_v1.zip` 放到 `/home/ljl/projects/flowr_root/`，保留以前的文件。执行：

```bash
cd /home/ljl/projects/flowr_root
source .venv/bin/activate
python -m zipfile -e scaffold_validation_batch_v1.zip .
python scaffold_validation_batch_v1/run_batch.py --prepare
```

这一步不做 GPU 生成。它读取旧输入记录及 `examples/` 的输入结构，排除已用输入编号、已用配体结构和重复结构。它不读取生成结果来挑数据。

输入仍限定为现有原生记录器支持的 cdk2、tyk2、ptp1b、bace。从符合输入条件的未用配体中按固定顺序选择 3 个，每个预先固定 42–51 这 10 个种子。输入需有可替换骨架、固定片段及连接位点邻近的固定内部键，这与当前候选机制的研究范围对应。不同配体未必来自不同蛋白；实际目标数会报告。“未使用”仅指可发现的本地记录，不能当作已经排除了模型预训练数据的严格测试集。

看见 `PREPARED: ... 30 baseline runs; 0 interventions.` 后执行：

```bash
python scaffold_validation_batch_v1/run_batch.py --run
```

它完成 30 条基线生成，保存真实网络调用与采样轨迹，并使用原记录器、原轨迹检查器和本次反馈实验同版本的评价程序。所有失败结果保留；运行报错与分子不合格分开，缺失评价不填成 False。

完成后提供这个文件：

```text
outputs/sh_validation_baselines_v1/validation_review.zip
```

同目录还保存 `frozen_plan.json`（生成前固定的方案）、`baseline_labels.csv`（各条输出的评价）和 `runs/`（完整原始轨迹）。完整轨迹后续回放要用，请保留。

中断后可再次执行 `--run`，完整生成不会重复。部分记录或运行错误会停止供检查，不删除原记录、不自动换样本。若准备阶段提示输入不足或历史记录无法识别，也会保存 `validation_review.zip`；此时先检查包中原因，不反复重跑或绕过身份检查。

## 3. 完成后在哪里停

本批次只做**新输入验证的基线准备**，不做内部干预，不证明机制泛化。完成后先核对统一评价、失败类型和真实原子映射。

配置文件已记录后续统一干预原则：同一 call=1、同一相对位置修正、每个位置 3 个等幅随机对照、原样回放检查。候选原子对由预处理输入的片段和连接关系决定；对所有符合规则的原子对分别检验，不按生成错误临时挑位置，不把旧样本的 2、3 号原子照搬过去。后续执行器还需接入新记录的实际映射；本程序没有假装完成这一步。

若新批次没有同类失败，记录“本批次未复现”；若干预没有优势，保留否定结果。不为每个新样本临时换层、换时刻、加幅度、换供体直到成功。先验证一种有明确证据的机制适用于哪些输入，不宣称能自动解释一切失败。

评价标准继续分开：化学有效性、连通性、固定片段化学保持、三维质量、骨架变化。新骨架无需与参考相同；严格外连键模式只作诊断。不会因为水分子检查没过，就忽略片段修复；也不会因为片段修复，就抹掉三维检查失败。
