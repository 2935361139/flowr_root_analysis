# FLOWR scaffold hopping：批量观察诊断入口 v1

研究目标：解释固定片段条件如何影响骨架连接；从真实生成记录中区分异常类型、位置、出现阶段，再研究内部计算及其因果作用。采用冻结的 FLOWR.ROOT，不需要为了这一步重新训练模型。

本包合并日常观察入口，读取已完成的统一评价和原有记录。它不生成新分子、不运行干预、不改变原评价标签、不覆盖旧文件。它还不是完整的模型内部原因分析器。

## 现在只需要这样操作

1. 将本文件夹 `scaffold_diagnostics_v1` 放在 `/home/ljl/projects/flowr_root/` 下。
2. 在 VS Code 的 WSL 终端进入项目并使用原来的环境：

```bash
cd /home/ljl/projects/flowr_root
source .venv/bin/activate
python scaffold_diagnostics_v1/diagnose_scaffold_runs.py \
  --quality-report outputs/sh_quality_multicase_v2/quality_report.json \
  --output-dir outputs/sh_diagnostics_v1
```

3. 预期依次显示 30 条记录的处理进度，最后显示 `Analysis completed: True`。
4. 上传 `outputs/sh_diagnostics_v1/diagnostic_review.zip` 即可。出错也保留并上传这个包，它会记录未完成的原因；不要先删除原记录或修改判断标准。

若输出目录已经存在，请换一个新的输出目录名，避免覆盖。若原记录整体移动了，可增加 `--records-root 新的记录父目录`；其子目录应保持原来的 `sh_record_CASE_seedSEED` 命名。

必须在原 FLOWR 项目下运行；需要 PyTorch、NumPy 和原记录中的 `inputs.pt`、全部 `forward_calls`、全部 `sampler_steps` 等文件。仅有审阅 ZIP 或最终 SDF 不足以判断生成中的时间变化。这个入口读取 CPU 上的记录，不重新加载模型或占用 GPU 进行生成。

## 它输出什么

| 输出 | 含义 |
|---|---|
| `summary.json` | 所有样本的异常类型、可观察的时间区间、解码变化、尚未定位的问题 |
| `candidate_observation_windows.json` | 按同一规则从轨迹得到的观察窗口，供下一步内部计算分析使用 |
| `run_XXX/connection_timeline.csv` | 每个固定原子的成键、身份、位移等逐帧记录 |
| `run_XXX/graph_timeline.csv` | 逐帧整体图连通性 |
| `run_XXX/connection_report.json` | 对应样本的评价、映射、轨迹摘要及解释范围 |
| `diagnostic_review.zip` | 便于回传的完整审阅包 |

`Analysis completed: True` 只表示记录处理完成，不表示所有异常都已定位，更不表示根因已确认。

支持的观察类型：固定中性碳的非芳香键超价模式、固定原子身份/内部键变化、整体图断连，以及解码前后固定化学结构的变化。未知键类别会标记为未知。芳香键的简单键级和不能通用于碳价态判错，相关情况留给化学检查并明确保留不确定性。

键角、水分子距离等 PoseBusters 问题会保留为“已发现、尚未定位到具体原子/时间”。不能用一次终态几何检查自动宣称是片段连接问题。新骨架与参考不同是允许的；外连键与参考完全一致只保留为严格诊断，不用它筛选失败样本。Murcko 骨架未改变单独报告。

## 时间定位怎样理解

主观察指标是：与终态问题对应的现象，从哪一条记录开始连续出现直到该记录流结束。它不是“最早造成失败的内部计算”。早期短暂、不持续的噪声变化不会自动成为该指标的起点。

网络调用编号和保存的采样帧编号是两个不同计数器，均从 0 开始。它们不能直接互换；采样帧有些键仍处于未知状态时，不能将未知当作正常。

现有 PTP1B seed47 的本地可读轨迹复核结果：固定原子 0 的中性碳超价模式，在网络预测中从调用 38（t≈0.38）持续到结尾；采样记录从帧 85 持续到结尾，但前一帧该价态模式仍不可判定。这两个数字是观察结果，不是两个“根因时刻”。解码修复还把该固定原子由 C 改为 S，需与网络生成问题分开报告。

候选窗口默认中心前后各 2 次调用，仅用于紧凑查看。后续因果扫描必须包括更早阶段和窗口外对照，不能只在这个小窗口寻找原因。

## 这次评价已经确认了什么

现有报告完成了 30 次生成轨迹、60 条解码评价记录，无执行错误。两个解码版本不能算作两个独立生成样本。

| 原始、未修复输出 | PTP1B | BACE | CDK2 |
|---|---:|---:|---:|
| 化学有效且连通 | 9/10 | 10/10 | 10/10 |
| PoseBusters 通过（分母为可评价者） | 2/9 | 0/10 | 10/10 |
| Murcko 骨架改变（分母为可评价者） | 9/9 | 10/10 | 4/10 |

- PTP1B seed47 原始输出的固定碳 0 键级和为 5，化学无效；修复解码后化学有效，但改动固定原子，不满足固定化学结构保持。
- 17 个原始输出未通过水分子距离检查；BACE seed45 另有键角检查不通过。这些还没有被定位为连接处的几何失败。
- 修复后的 PTP1B seed47 还有内部能量与水分子距离检查不通过；该分子不属于上面的 17 个原始有效输出。
- CDK2 的 6 个骨架未变样本不是连接失败。

这些是小样本流程检查，不足以声称某种内部机制在不同复合物上普遍成立，也不是分子活性验证。

## 下一阶段的固定流程

1. **统一观察。** 用本入口处理现有全部记录，支持的问题自动定位，暂不支持的明确列出。相同输入、相同版本应给出相同结果。
2. **建立可重复的失败类型。** 从更多合适的固定片段任务中收集同类连接异常与正常对照。目前明确的固定碳超价只有一个原始样本，不足以验证机制泛化。新增样本用于分析与检验，不是给解释器预训练。
3. **适配内部扫描。** 复用现有回放和子模块记录工具，统一模块列表、时刻网格、评分指标、对照和停止条件。核实原子对应、坐标系与随机性后，才实施激活替换。不同种子的相同生成槽位编号不代表同一个化学原子，不能直接盲目替换。
4. **检验因果解释。** Meltdown 的激活替换本身参与定位关键计算。对候选位置做受控替换，并与随机位置、其他时刻、匹配强度等对照比较，检查后续更新和最终连接。未获得证据就报告未定位/不支持，不能无限增加单例猜测。
5. **检验迁移。** 冻结诊断与干预规则，在未参与规则设计的复合物上测试；既看失败改善，也看正常输出是否受损。输入原子贡献分析是另外一项证据，不能代替因果检验。

Meltdown 参考：<https://arxiv.org/html/2602.11130v2>。该研究针对特定的三维重建碎裂现象，通过受控对照、模块与时刻扫描、内部表征分析和干预形成机制解释；它不是输入任意失败即可自动给出唯一根因的通用软件。迁移的是实验设计，FLOWR 模块、分子条件和目标指标仍需专门适配。

## 已做验证及其边界

本入口通过语法/命令行检查，以及 `validation_results.json` 所列 109 项检查。实际数据覆盖现有 10 条 PTP1B 轨迹的 101 次网络调用、101 个采样帧，以及 3 个实际终态完整张量；另外核对了全部 30 条记录的终态分流。检查还包括原子编号置换、非连续固定掩码、断连与超价区分、未知键处理、严格参考差异不判失败。
